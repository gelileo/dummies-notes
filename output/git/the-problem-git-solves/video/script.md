## A version (a saved snapshot of your whole project)

A version (a saved snapshot of your whole project)

Here's your project — one folder holding all its files, the ones you keep editing.

Saving a version is like taking a photo of the entire folder exactly as it looks right now. That frozen photo is version 1.

You keep working and change a file — styles.css gets edited. Your live folder moves on, but the photo you took doesn't.

Take another photo and you get version 2: the whole folder again, now with the edited file baked in.

Because each version is a complete copy, loading one restores every file at once — the whole folder snaps back to exactly how it looked then.

## The problem git solves

The problem git solves

Here's a folder most of us know: essay_final.docx, then v2, then the one you swear is actually final. Three files, nearly identical names.

The trouble: you can't tell what changed between them, you're scared to delete any, and sharing one means emailing a whole copy.

Git flips this around. You keep just one file in your folder, the clean copy you actually edit.

Behind the scenes, git remembers every version you saved: a timeline of snapshots, so nothing is ever lost.

Need an old draft? Roll back to any past version on the timeline. One clean folder in front, the full history safely behind it.
